# devpm-weekly-report · 개발 진행 주간 리포트 AI

> Jira 이슈 CSV를 넣으면 **진척률·지연·막힌 작업·버그는 코드가 집계**하고, **AI가 주간 리포트를 쓰고**, AI가 쓴 숫자와 이슈 번호는 **코드가 다시 대조**합니다. PM은 검토만 하고 공유합니다.

| | |
|---|---|
| **기간** | 2026.11 |
| **성격** | 개인 프로젝트 (개발 PM 업무 자동화) |
| **데모** | https://chanhyeok-pm.cloud/report/#demo |

<br>

## 문제

개발 PM은 매주 이슈 트래커를 훑어 진척률을 세고, 늦어진 작업과 그 작업 때문에 기다리는 작업을 찾고, 버그 현황을 정리해 리포트를 씁니다.
이 일은 반복적이지만, **숫자가 틀리면 팀의 판단이 틀어집니다.** 그래서 AI에 통째로 맡기기보다 역할을 나눴습니다.

## 구조

```
[이슈 CSV]  Jira 내보내기 형식 (영문 열 이름도 인식)
    ↓
[코드: 지표 집계]  진척률(작업·포인트) · 단계별 진행 · 이번 주 계획 대비 완료율
                  기한 초과 · 막힌 작업 · 연쇄 영향(뒤에서 기다리는 작업 수)
                  버그 심각도·증감 · 외주 재작업 · 마일스톤 버퍼
    ↓
[AI: 리포트 작성]  Amazon Bedrock (Nova Pro) · 요약 / 리스크 Top 3 / 다음 주 우선순위 / 결정이 필요한 사항
    ↓
[코드: 검증]  리포트 속 이슈 번호·숫자가 집계에 없으면 경고 (한글 조사가 붙은 경우까지 대조)
    ↓
[PM]  검토 후 Slack·Jira로 공유 (마크다운 복사)
```

| 원칙 | 이유 |
|---|---|
| 숫자는 AI가 만들지 않는다 | 진척률·버퍼가 틀리면 우선순위 판단이 틀어짐 |
| AI가 쓴 글을 코드가 대조한다 | 집계에 없는 이슈 번호나 숫자가 섞이면 공유 전에 잡아냄 |
| 리스크는 영향 순으로 | "늦은 작업"보다 "그 작업 때문에 기다리는 작업 수"가 큰 것부터 |

## 시연 데이터

[`data/sample_issues.csv`](data/sample_issues.csv)는 **가상의 "신규 캐릭터 출시" 프로젝트**입니다 (기획 → 원화 → 외주 모델링·애니 → 스킬 구현 → VFX·SFX → 밸런스 → QA → 현지화·공지, 작업 22개·버그 5개). 실제 게임이나 회사의 데이터가 아닙니다.

## 검증

```bash
pip install -r requirements.txt pytest
python -m pytest -q      # 9 passed
```

진척률, 계획 대비 완료, 기한 초과·늦은 완료, 막힘과 연쇄 영향, 버그 집계, 마일스톤 버퍼를 손으로 센 값과 비교하고, AI 글 검증이 지어낸 이슈 번호·숫자를 잡아내는지 확인합니다.
